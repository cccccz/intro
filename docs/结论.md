1. 目的是更好的信息传播：让自己的探究过程方便他人接上，从而实现共同的知识进步，减小人与人之间的认知摩擦。
2. 系统只提供基础能力。写给谁、写多短、侧边停在哪、是否重复写，都由笔者决定，不写成系统约束。
3. 这是一块工作区。宿主是竖排材料（正文、PDF 等），本身完整可读。
4. 侧边挂在前一层里被选中的那段内容上（铆点），不是挂在整篇或整节上。
5. 侧边也是宿主，可以再划、再挂，横向延伸。读者可以只走宿主，也可以沿锚点一层层打开。
6. 置顶带是同一类笔记区，只是更矮、放在正文上方，多块往右加格。钉的是选定内容（源），不是标题或整篇名字。置顶投影源文；文本选区允许在置顶内编辑，保存须校验来源并写回原笔记对应选区，不产生独立副本；PDF 区域只读。置顶不新长铆点树：点置顶带里的铆点不得打开或伸长树，置顶不是开链入口；侧边从列视图打开。只能人为钉；系统不得因为源滚出画面而把侧边塞进置顶带。
7. 主文件加铆点会自然形成树。树是结构的形状，不是另一种笔记格式。
8. 同一套钉数据可以有三种看法，都不是另一种笔记格式：大纲树看从属和深度；缩略图看工作区里有哪些篇（是篇/件清单，不是单棵树的深度卡片）；色块地图以宿主全文为纵轴、深度为横轴，等大格子，空格数量表示正文里的距离，用来看分布和有多深。色块地图不是导航：不靠点格子跳进列或打开侧边。写者主界面仍是列。缩略图（网格）M1 不做、先不实现；假页面网格只是演示，不是规格。
9. 高亮之后可以新建笔记，或复用已有笔记，或节选大笔记中的一小段。节选是指向（某篇 + 范围），不是默认复制。
10. 复用之后，同一篇或同一段可以有多个父锚点，整体是有向图；当前阅读路径仍可看成树。
11. 需要搜索：用来发现某件事是否已经有笔记，再决定链接复用还是新写。重复书写是允许的；能复用时复用更合适。
12. 宿主优先是论文、书、PDF 和纯文本。
13. 单人使用，没有账号，也不做多人同时编辑。
14. 写与读不同：笔者可以有自己的一整库；读者不进入笔者的库。
15. 分享是导出，不是靠账号链接。笔者库内可以互相链接；对外是把东西交出去。
16. 导出由笔者选择，类似 docx 与 pdf：一是可再打开的工作区包（整库，或按披露裁过的子库）；二是渲染件。披露多少由制作者决定。
17. 仅渲染时默认用 HTML：其他便利传输格式难以承载开合侧边等任意逻辑，HTML 可以。
18. 铆点保真度是难题，尤其在 PDF 上。
19. PDF 能力在目标上要支持。第一版文本回路不必被 PDF 挡住；PDF 宿主另走侧车（第 40 条），不是把 PDF Annot 当权威。
20. 写者主界面定为 A：横向多列，列表示深度。下一列是从上一列划开的侧边所在的 panel，不是每篇侧边独占一列。
21. 默认同时只看见 3 列（三层）；这个数量用户可以自己改。
22. 这是视口上限，不是树的最大深度：链条仍可任意深，看得见的是连续几层；同层多支叠在该层 panel 里。
23. 给读者的 HTML 导出用 B：宿主加一侧抽屉，或在原处替换；读者不必真的打开无限列。
24. C（无限画布）留给以后，不是写者主壳，也不是第 8 条的色块地图或缩略图。节点之间连线的知识图谱不是 intro 的结构看法。
25. D（读者页边注风格）可在 PDF 里程碑再强调，不是写者第一版主界面。
26. 写者端是本地 Electron 壳，不是网站，也不用 Tauri。
27. 工作区界面仍是壳里的 HTML/TypeScript，所以 HTML 导出可以共用同一套渲染。
28. 选 Electron 主要是为了应用内引擎就是 Chromium（排版、数学、以后 PDF.js），接受安装包更重。
29. 钉的权威放在正文里的特殊标记上，不是另存一份以下标为主的权威 graph 表；这是做法 A。
30. 同一篇里允许嵌套，不支持交叉；交叉视为损坏，不要猜。
31. 加上标记与清除标记成对：清除（用户所说的 inverse）是删掉全部约定标记、正文一字不改，用来导出干净文本；屏幕上的宿主也可以显示清除后的结果，磁盘仍保留标记。
32. 清掉(加上去(干净正文, 钉)) 应等于原来的干净正文。
33. 工作区还需要解析：认出标记，得到钉的树（id、嵌套、连到哪）。解析给开侧边用，清除给只要文章用。两者都是对同一套标记的线性扫描，嵌套用栈。
34. 「谁钉过这篇」若需要，用可重建的倒排缓存，不是 inverse，也不是第二份权威；丢了就全库解析重建。
35. 标记里带稳定 id，不带「第几字」。标记格式尚未选定，下一步才谈，不假装已经定了括号长什么样。
36. 未 Pin 的子侧边卡片是否画出来，跟上一列里源高亮是否还在该列视口里走：源不在视野内就不画对应卡片（以及导线）。这是视口规则，不是合上；铆点仍在，源滚回来再画。手动 Pin 的侧边按第 42 条保持显示。侧边所在的那一列本身一直占位，直到 Close 或 Delete，不得因视口显隐而收列或改列宽。
37. 屏幕上的公式是渲染结果。划进置顶区或在工作区里再投影的选区，以源文为准（含 TeX），再走同一套渲染；不能把已排好的画面当作可再渲染的笔记。
38. M1 必须走完写回路：划选 → 写入铆点标记 → 新建或打开一篇侧边宿主 → 再划、再挂。假页面里预埋的 `<mark>` 只是演示，不是产品路径。三种看法、导出、PDF 都不得挡住这条回路。
39. 写者壳可以用视图像反馈标出铆过的选区，并在「当前打开的铆点」与「因此打开的侧边列」之间画导线。这是视图像，不是第二种权威：高亮/导线几何不写入正文或 `.intro.md`。文本宿主的权威仍是做法 A 的铆点标记（稳定 id）。导线只表示这一对打开关系，不是知识图谱。源高亮滚出该列视口则不画未 Pin 的对应侧边卡片（第 36 条），不是合上，也不得把整列 `display:none`。Pin 保留卡片但不画来源已不可见的导线。换宿主介质只换「rivetId → 矩形列表」的投影：textarea/HTML 与 PDF.js 页几何共用这一接口。
40. PDF 宿主的钉不写回 PDF 文件，也不把 PDF 二进制当成可下标的正文。磁盘上是不可变的 `{id}.pdf` 副本 + `{id}.intro.host.json` + `{id}.intro.overlay.json`（页 + 轴对齐矩形；QuadPoints 只按四点 min/max 归一）。侧边仍是 `{id}.intro.md`，可再划再挂。可选摘录以后再加，不是重挂所必需。这是侧车权威，不是第二种文本 graph 表，也不采用 MarginNote 式「拷进应用再改 PDF」作主路径。
41. 保护已有 library。升级先备份，在副本上验证打开、保存、重开、侧注和 PDF，不静默迁移。正式库（包括 `C:\Users\Zheng\Desktop\paul`）不是测试数据。不要两个进程同时编辑同一个库。
42. 侧边可以 Pin/Unpin。Pin 的是当前挂接下的整篇侧边，留在原列，来源或上游卡片因滚动不可见时仍显示；不是把选区送进顶部置顶带，也不锁死屏幕坐标。取消 Pin 后恢复来源显隐规则。同一篇在不同挂接下可分别 Pin；状态按资料库、宿主篇与铆点记在应用偏好中，不修改 library 格式。关闭重开挂接后保留 Pin 偏好，但不自动打开任何侧边。显式 Close 或解除挂接仍收起对应整条子树，即使子树中有 Pin。未 Pin 的后代继续跟随自身来源的可见性；单独 Pin 的后代不受上游滚动隐藏影响。层级导航和侧列自己的滚动仍正常工作。

43. 数学公式内部可挂 side：选中某项映射到源码区间，显示只高亮相应数学元素；不向 TeX 注入锚点占位符。重复项按位置区分。正文编辑重定位锚点；删除或跨越来源时本版拒绝保存并保留可恢复草稿，须先撤销并解除挂接，不能静默丢弃或错挂笔记。
44. Rendered 数学标注按同一锚点的连续区域显示整体底色及悬停外框，不逐个符号描框；跨行或相隔较远的部分分别显示。
45. Ask Codex 复用文本、公式及 PDF 的现有选区，在右键菜单发起解释；用户可补充问题。选区及附近原文发送给用户登录的 Codex，完成后由 intro 校验来源并保存普通 side。生成中不锁住阅读；来源变化时保留回答草稿，不按旧位置强行挂接。成功回答默认 Pin，便于用户翻页后继续阅读，可自行取消 Pin。账号登录属于外部 Codex 服务，intro 不建立账号体系；已有 library 格式和离线阅读不依赖 Codex。

46. Codex 按用户问题自由生成笔记，不固定数学导师角色。提问窗口选择账户支持的模型及推理强度，并控制联网；可按需读取关联 PDF 的任意页及目录、关联笔记正文。side 的 AI 菜单区分新增回答和改进当前笔记；改进必须先预览再应用，保留标题、稳定 ID 和既有关系，可在后续未编辑时撤销。不能可靠定位被改写的子 side 来源时，保留修改稿并拒绝覆盖。


47. Ask Codex 按问题需要检索：已有上下文充分时直接回答；缺少依据、定义或引用时主动回读或搜索。关联 PDF 全文搜索使用可重建的带页码 Markdown 辅助缓存，不改变 library 权威文件，不建数据库；空白扫描页和搜索未命中不得被当作原文不存在。可按页读纯文字，也可读原页图片核对。OCR 暂未接入。
