# 文本宿主铆点标记（P1 草案）

正文里的标记是钉的权威（结论第 29 条，做法 A）。不另存一份以下标为主的 graph。不使用 mockup 预埋的 `<mark class="rivet">`。

同一文件文首可以有 YAML frontmatter（目前只用 `title:` 显示名）。那不是第二种 id，也不进入下面的 rivet 扫描；parse / strip / add 只处理关闭 `---` 之后的正文。

本草案只服务**文本宿主**。PDF 宿主不把 `<<r>>` 写进 PDF 字节，也不假装字符下标；铆点在 `{id}.intro.overlay.json`（见 `app/pdf/` 与 `app/README.md`）。PDF 侧边仍是 `{id}.intro.md`，同一套 frontmatter。

## 定界符

一对标签包住被钉的选区。闭标签带 `id`，才能在线性扫描时认出交叉。

```
<<r id="RIVET_ID" to="PIECE_ID">>选区正文<</r id="RIVET_ID">>
```

无侧边（尚未挂篇）时省略 `to`：

```
<<r id="RIVET_ID">>选区正文<</r id="RIVET_ID">>
```

| 部位 | 字面量 | 说明 |
|---|---|---|
| 开标签前缀 | `<<r` | 第三字是 `r`，不是 `/` |
| 闭标签前缀 | `<</r` | |
| 标签结束 | `>>` | 标签内不得出现 `>>` |
| 属性 | `name="value"` | 双引号；空白分隔 |

规范写出的顺序是 `id` 再 `to`。解析按名字认属性，不依赖顺序。未知属性解析时忽略；`add` 重写只输出 `id` / `to`。

标签必须在**同一行**内闭合，且总长不超过 256 个 UTF-16 代码单元。跨行的 `<<r`…`>>` 不当标签，按普通正文留下。

## 属性

| 属性 | 在哪 | 含义 |
|---|---|---|
| `id` | 开、闭都必须有 | 这颗钉自己的稳定 id，不是「第几字」 |
| `to` | 仅开标签，可省略 | 侧边那一篇的篇 id（不是路径） |

id 字符：`[A-Za-z0-9][A-Za-z0-9_-]{0,127}`。实现里新 id 用 ULID（26 位 Crockford：`0-9A-HJKMNP-TV-Z`）。

`to` 是篇 id。库把 id 收成路径；标记里不写路径、不下标。

偏移只用于**这一次划选**（编辑器交来的区间）。写入之后权威是标签，不是 start/end。

## 嵌套

允许。同一篇里外钉包内钉。解析用栈：开则入栈，闭且 `id` 等于栈顶则出栈，挂到父钉（或根）。

```
外层 <<r id="A" to="p1">>…… <<r id="B" to="p2">>内层<</r id="B">> ……<</r id="A">>
```

两条钉区间相同：按 `add` 收到的顺序，先到的在外。相邻（`end === 另一条 start`）不算交叉。

## 交叉 = 损坏

交叉不能靠未标号的闭标签表示；所以闭标签带 `id`。

```
<<r id="A" to="p1">>aaa <<r id="B" to="p2">>bbb<</r id="A">>ccc<</r id="B">>
```

闭 `A` 时栈顶是 `B` → **crossing**。不要自动补闭、不要重排、不要改正文。只报告损坏。

其它损坏（同样不修补）：

| kind | 何时 |
|---|---|
| `crossing` | 闭标签 id 在栈里，但不是栈顶 |
| `orphan-close` | 闭标签时栈空，或 id 根本不在栈上 |
| `unclosed` | 扫完栈里还有开着的钉 |
| `duplicate-id` | 两个开标签同一 `id` |
| `missing-id` | 开或闭没有 `id` |
| `malformed` | 像标签（`<<r`/`<</r` … `>>`）但属性写坏了 |

损坏的篇：`parse` 仍扫完；树里只放**正常闭合**的钉。未闭合那一支上的子钉也不提升（那是修补）。`add` / `addMark` 遇到已损坏的宿主或新区间会交叉，拒绝写入。

## 清除（inverse）

`strip` 删掉全部约定标签（含属性写坏但已用 `>>` 收住的），标签之间的正文一个字都不动。

```
strip(add(clean, rivets)) === clean
```

屏幕可以显示 strip 后的宿主；磁盘仍留带标记的正文。

P1 没有转义。宿主里不要写 `<<r` 或 `<</r` 再紧跟一行内的 `>>`，否则会被当成标签并在 strip 时拿走。以后若真要字面量，再加转义，不在本轮猜。

## 偏移约定（只给 API）

`add` / `addMark` 的 `start`/`end` 是 **strip 之后正文**上的 UTF-16 下标（JS 字符串下标），半开区间 `[start, end)`。`parse` 给每颗钉填 `cleanStart` / `cleanEnd`，方便 P2 在干净视图上画选区；这两数是派生的，不是权威。

## 不是什么

- 不是 HTML，不是 `<mark>`，不是 mockup 语法
- 不是 CriticMarkup，不是侧车 JSON / 下标表
- 本轮不规定 Markdown 渲染、公式、导出
- P2 屏幕 **Rendered** 只投影：先 `parse` / `strip`（铆点），再对干净正文做 markdown。不得对 `<<r>>` 定界符跑 markdown（`**` / `#` 等不能拆标记）
