# Ask Codex

## 使用

1. PDF 左键拖出选区，或在 Source／Rendered 文本、公式中划选。
2. 右键 **Ask Codex…**，直接发送默认解释请求，或者写自己的问题。
3. 可以继续阅读或翻页；成功后自动创建并 Pin 一个普通 side。
4. 生成时原文变化、保存失败或程序中断，回答草稿从顶部 **Codex 回答** 查看。可以复制源码；仍匹配原选区的回答可以尝试重新挂接。

需要官方 Codex CLI（已验证 0.153.4 和 0.154.0-alpha.6.2）和 ChatGPT 登录。程序接受数字版本 >= 0.153.4 的正式版及预发布版，再通过 App Server 握手验证实际兼容性。程序首先使用 `INTRO_CODEX_BIN` 指定的路径；未指定时自动查找 PATH 和 Windows Codex 安装目录（含版本子目录），验证版本后选择兼容的可执行文件，不要求从 Codex 开发环境启动。未登录时点击 **连接 Codex**，在浏览器完成官方登录后重新提问。没有复制或导出认证文件。

一次生成一个回答。提问窗口从账户模型目录加载所有可选模型及对应推理强度，记住选择；PDF 图片输入会标明不支持图片的模型。默认允许联网，可在每次提问时关闭。

提示词定位为通用笔记助手，由用户问题决定内容与组织方式，不再强制数学推导。最终仍为标题、Markdown 正文和引用。网页资料使用可点击的 Markdown 链接，在系统浏览器打开。

PDF 初始仍提供选区图像、本页和前后页，但工具可以读取关联 PDF 的任意有效页码及目录，不限于附近三页。给 side 提问时，初始提供当前笔记全文（超过十万字符时可继续分段读取）、直接来源片段和祖先／子 side 的关系目录；模型按需读取关联笔记、PDF 页面。已支持按需全文短语搜索和带页码的 Markdown 缓存；OCR 尚未接入，见 [`docs/history/OCR_NOTES.md`](../../docs/history/OCR_NOTES.md)。

side 卡片的 **AI…** 菜单包含「向这篇笔记提问」和「改进这篇笔记」。后者先显示原文／修改稿，点击应用才覆盖当前正文。保留原标题、ID 和未知元数据；已有子 side 的来源片段能唯一定位才保留挂接，否则拒绝覆盖并留下草稿。可撤销此次改进；笔记后来又被编辑时不会强行撤销覆盖。

## 实现与数据

- `transport.ts`：主进程 stdio 协议连接、请求关联和关闭处理。
- `service.ts`：认证状态、模型发现、请求状态及只读上下文工具。
- `commit.ts`：来源版本校验、逐文件原子替换、跨文件可恢复提交。
- renderer 的 `pdf-view.ts`：复用 PDF.js 做离屏渲染，独立于滚动时销毁的页面 canvas。
- `codex-answers/*.json` 位于应用配置目录，保存回答草稿及提交计划。图片只在本次请求的内存里保留，不写入 library。
- 完成的笔记仍是普通 `.intro.md`，PDF 原文件保持不变。自动 Pin 仍使用现有应用显示偏好。

当前采用 App Server 的实验性 `dynamicTools`，将读上下文直接回调给 intro，避免每个请求另起 MCP 进程。前期探针验证了 MCP；产品适配器改用动态工具后也进行了真实调用验证。它没有跨机器会话续接、跨库检索或公共代理服务。

App Server 复用现有 Codex 登录及宿主配置，通过进程参数关闭执行／编辑工具入口，联网按提问窗口选项启用。它不是独立操作系统隔离容器；原文访问由本次上下文工具限定，未引入让模型直接修改 library 的工具。
